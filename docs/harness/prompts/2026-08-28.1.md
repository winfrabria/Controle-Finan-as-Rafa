# Prompts 2026-08-28.1

O verificador passa a tratar `initialFindings` como hipóteses não confiáveis.
Para confirmar uma hipótese financeira ou de data, ele deve reler o documento
original, devolver o mesmo código, os mesmos valores ou datas e preencher
`confirmsInitialFindingCode`.

Quando o original não sustentar exatamente a hipótese, o verificador não deve
repeti-la. Página ausente, texto da extração e a própria hipótese inicial não
servem como evidência de confirmação. Achados independentes usam
`confirmsInitialFindingCode=null`.

As proteções contra prompt injection, chain-of-thought, camadas econômicas
sobrepostas e `TOTAL_MISMATCH` sem cobertura completa permanecem inalteradas.
